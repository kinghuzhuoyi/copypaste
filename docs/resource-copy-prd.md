# 跨决策资源拷贝产品需求文档

版本：v1.0  
日期：2026-07-06  
适用项目：`resource-copy-app`  
适用范围：决策引擎内规则、组件、参数等资源跨决策流/版本拷贝弹窗

## 1. 背景

决策引擎中的规则、计算组件、参数、变量、模型等资源存在复杂引用关系。业务在搭建新场景或迁移策略时，需要将来源决策流中的规则或组件批量拷贝到当前目标决策流中。

由于一个规则可能直接或间接依赖多个组件、参数、变量、模型，拷贝前必须识别依赖链路、目标侧已有资源、可复用资源、命名冲突和无法拷贝的冲突项。当前功能以大系统中的弹窗形式承载，需要在有限空间内完成选择、校验、冲突处理、归类和提交。

## 2. 目标

1. 支持从来源项目、来源决策流、来源版本中检索并选择待拷贝资源。
2. 支持规则和组件的大列表展示、检索、分组、多选和已选汇总。
3. 支持调用后端校验接口，展示资源冲突、可拷贝达成率和完整依赖血缘。
4. 支持业务在提交前处理可重命名冲突，并为可拷贝规则选择或新建目标规则包。
5. 支持提交拷贝，并展示包含依赖资源在内的拷贝结果统计。
6. 前端保留 mock 模式，方便无后端环境下演示；切换真实后端时不需要修改页面逻辑。

## 3. 非目标

1. 前端不计算资源依赖、冲突类型、复制/复用/直接调用/终止数量。
2. 前端不编辑规则、组件、参数、变量、模型的定义内容。
3. 前端不实现资源编码唯一性、类型兼容性、循环依赖等复杂业务判断。
4. 当前版本不设计异步任务轮询；拷贝保存接口按同步返回结果处理。
5. 当前弹窗不负责选择目标决策流，目标上下文由宿主系统或环境配置注入。

## 4. 用户与场景

主要用户：决策平台业务人员、规则运营人员、策略配置人员。

典型场景：

1. 从历史版本复制一批成熟规则到当前目标版本。
2. 从其他决策流复用某类规则包下的规则。
3. 拷贝规则时一起带入其依赖组件和参数。
4. 遇到目标侧已有同编码资源时，由业务确认重命名或跳过。
5. 将可拷贝规则归类到目标规则包，便于目标场景维护。

## 5. 核心定义

| 名称 | 说明 |
| --- | --- |
| 来源决策流 | 被复制资源所在的决策流。 |
| 来源版本 | 被复制资源所在的决策流版本。 |
| 目标决策流 | 当前弹窗所在场景对应的决策流。 |
| 目标版本 | 当前弹窗所在场景对应的目标版本。 |
| 初始选择资源 | 用户在第一步主动选择的规则或组件。 |
| 依赖资源 | 后端基于初始选择资源解析出的下游依赖资源。 |
| 可拷贝资源 | 后端判定可以复制到目标场景的资源。 |
| 冲突资源 | 后端判定存在编码、定义、类型或引用问题的资源。 |
| 资源血缘 | 本次拷贝涉及的初始资源和依赖资源树。 |
| 规则包归类 | 将可拷贝规则分配到目标规则包，可选择已有规则包或输入新规则包名称。 |

## 6. 用户流程

1. 用户在目标决策流中打开“跨决策资源拷贝”弹窗。
2. 系统展示目标场景信息，包括目标项目、目标决策流、目标版本。
3. 用户依次选择来源项目、来源决策流、来源版本。
4. 系统查询来源版本下的规则和组件，按规则包或组件类型分组展示。
5. 用户检索并多选规则或组件，右侧展示已选资源，可取消选择。
6. 用户点击“下一步”，前端提交已选资源 ID 给后端做拷贝校验。
7. 系统展示校验结果，包括可拷贝达成率、冲突信息、资源血缘、目标规则包归类。
8. 用户处理可重命名冲突，确认无法解决的冲突项会终止对应资源拷贝。
9. 用户为可拷贝规则选择目标规则包，也可以输入新规则包名称。
10. 用户点击“继续拷贝”，前端提交后端返回的校验结果、重命名结果和规则包归类结果。
11. 系统展示拷贝完成页，包括复制、复用、直接调用、冲突、跳过数量。

## 7. 功能需求

### FR-01 目标上下文展示

弹窗打开后展示当前目标场景信息。目标上下文包括目标项目、目标决策流编码、目标决策流名称、目标版本、目标场景名称。

当前实现中目标上下文来自前端环境配置或宿主系统注入。真实后端接口文档暂未提供目标上下文查询接口，因此前端不从 `/copy/*` 接口推导目标场景。

### FR-02 来源场景选择

来源场景选择包含项目、决策流、版本三级。

项目支持按名称检索，调用 `GET /copy/projects/{projectName}`。  
决策流支持按编码或名称检索，调用 `GET /copy/process/{projectName}/{process}`。  
版本列表按决策流编码查询，调用 `GET /copy/version/{processKey}`。

切换上级选择时，下级选择和资源列表需要清空，避免跨来源状态残留。

### FR-03 来源资源展示与选择

来源版本选择完成后，前端调用 `POST /copy/resources` 查询资源。

资源列表需要支持：

1. 按名称或编码检索。
2. 分组展示，规则按规则包展示，组件按组件类型展示。
3. 大列表滚动展示，适配上百条规则或组件。
4. 多选资源。
5. 已选资源集中展示，支持单个取消和清空。

前端仅提交用户选择的资源 ID，不自行展开依赖。

### FR-04 拷贝校验

用户点击下一步后，前端调用 `POST /copy/copyValidated`。

请求参数包括：

1. `sourceIds`：用户选择的资源 ID 列表。
2. `sourceProcessKey`：来源决策流编码。
3. `sourceProcessVersion`：来源版本。
4. `targetProcessKey`：目标决策流编码。
5. `targetProcessVersion`：目标版本。

后端返回本次拷贝的冲突项、可拷贝项、完整血缘树和统计结果。前端只做展示和轻量交互，不重新判断资源是否可拷贝。

### FR-05 冲突信息展示

资源冲突页面需要展示：

1. 冲突资源编码、名称、模块类型。
2. 冲突原因 `conflictMsg`。
3. 后端建议的新编码 `itemNewCode`。
4. 目标规则包信息 `pkgId`、`pkgName`。
5. 前端处理方式：可重命名、冲突终止。

当后端返回 `itemNewCode` 时，前端展示重命名输入框，允许业务修改后提交。无法通过重命名解决的冲突项只展示原因和终止提示，不允许前端强行改为可拷贝。

### FR-06 计划拷贝目标达成率

资源冲突页面展示后端返回的整体统计：

1. 计划复制总数 `copyTotal`。
2. 可复制总数 `copyableTotal`。
3. 可复制达成率 `copyableRate`。
4. 冲突数量 `conflictCount`。
5. 复制、复用、直接调用、跳过数量。

达成率用于帮助业务判断是否继续拷贝。前端不得基于页面筛选结果重新计算达成率。

### FR-07 拷贝血缘展示

血缘区展示 `copyModuleLineageTrees` 的完整树结构。

每个节点需要展示：

1. 资源类型 `moduleDesc` 或 `module`。
2. 资源编码 `itemCode`。
3. 资源名称 `itemName`。
4. 拷贝处理方式 `typeTagDesc` 或 `typeTag`。
5. 引用的变量、模型、入参、过程变量、插件等列表摘要。
6. 子组件依赖。

血缘展示需要支持搜索、按处理方式筛选、展开/收起和层级缩进。大依赖场景下默认保持信息密度，不使用高饱和大色块。

### FR-08 目标规则包归类

对于后端返回的 `copyableItems`，前端需要展示目标规则包归类控件。

用户可以：

1. 选择已有目标规则包，来源为 `GET /copy/pkg/{processKey}/{processVersion}`。
2. 输入新的规则包名称。

提交保存时，前端将每个可拷贝项的 `pkgId`、`pkgName` 合并到 `copyableItems` 后提交。若新建规则包没有 `pkgId`，则提交 `pkgName`，由后端处理创建或匹配。

### FR-09 拷贝提交

用户确认继续拷贝后，前端调用 `POST /copy/copySave`。

提交内容包括：

1. 后端校验返回的 `conflictItems`，其中可重命名项带上用户最终确认的 `itemNewCode`。
2. 后端校验返回的 `copyModuleLineageTrees`。
3. 后端校验返回的 `copyableItems`，其中带上用户最终确认的目标规则包 `pkgId`、`pkgName`。
4. 来源和目标决策流编码、版本。

提交后展示后端返回的保存统计。

### FR-10 Mock 与真实后端切换

前端保留 mock 功能，便于脱离后端演示和前端联调。

配置方式：

| 配置项 | 说明 |
| --- | --- |
| `VITE_USE_MOCK_API=true` | 使用本地 mock 接口。 |
| `VITE_USE_MOCK_API=false` | 调用真实后端接口。 |
| `VITE_RESOURCE_COPY_API_BASE_URL` | 真实后端接口基础地址。 |
| `VITE_TARGET_*` | 目标场景上下文配置。 |

真实后端接入时，研发只需要切换环境变量，不需要修改组件内部逻辑。

## 8. 前后端职责边界

| 模块 | 前端职责 | 后端职责 |
| --- | --- | --- |
| 来源选择 | 展示选择器、搜索输入、级联状态清理 | 返回项目、决策流、版本列表 |
| 资源选择 | 展示资源分组、多选、已选汇总 | 返回来源版本可选资源 |
| 依赖解析 | 不解析依赖 | 根据资源 ID 解析完整依赖树 |
| 冲突判断 | 展示冲突、收集重命名输入 | 判断冲突类型、原因、是否可重命名 |
| 达成率统计 | 展示后端结果 | 计算 copyTotal、copyableTotal、copyableRate |
| 血缘展示 | 渲染树、搜索、筛选、展开收起 | 返回完整血缘和每个节点处理方式 |
| 规则包归类 | 收集每个可拷贝项的目标规则包 | 返回目标规则包列表，保存时处理归类 |
| 拷贝保存 | 组装用户确认后的保存请求 | 执行复制、复用、重命名、跳过等最终动作 |
| 完成结果 | 展示保存结果 | 返回保存统计 |

## 9. 后端接口依赖

### 9.1 项目查询

`GET /copy/projects/{projectName}`

返回项目列表，用于来源项目下拉检索。

### 9.2 决策流查询

`GET /copy/process/{projectName}/{process}`

返回决策流列表，用于来源决策流下拉检索。

### 9.3 版本查询

`GET /copy/version/{processKey}`

返回版本列表。版本状态包括草稿、生效、灰度、下线等。

### 9.4 目标规则包查询

`GET /copy/pkg/{processKey}/{processVersion}`

返回目标版本下已有规则包列表。

### 9.5 来源资源查询

`POST /copy/resources`

请求体：

```json
{
  "name": "",
  "sourceProcessKey": "",
  "sourceProcessVersion": ""
}
```

返回来源版本下的资源分组。

### 9.6 拷贝校验

`POST /copy/copyValidated`

请求体：

```json
{
  "sourceIds": ["resource-id"],
  "sourceProcessKey": "",
  "sourceProcessVersion": "",
  "targetProcessKey": "",
  "targetProcessVersion": ""
}
```

返回冲突项、可拷贝项、血缘树和统计信息。

### 9.7 拷贝保存

`POST /copy/copySave`

请求体包含：

1. `conflictItems`
2. `copyModuleLineageTrees`
3. `copyableItems`
4. `sourceProcessKey`
5. `sourceProcessVersion`
6. `targetProcessKey`
7. `targetProcessVersion`

返回：

```json
{
  "conflictCount": 0,
  "copyCount": 0,
  "directCount": 0,
  "reuseCount": 0,
  "skipTotal": 0
}
```

## 11. 页面设计要求

1. 弹窗内使用三步式结构：选择资源、校验与处理、完成结果。
2. 选择页左侧展示来源资源，右侧展示已选资源，避免用户在长列表中丢失选择上下文。
3. 校验页顶部先展示结果概览，再展示冲突，再展示血缘和规则包归类。
4. 血缘区使用低饱和标签、表格化层级和清晰间距，避免大面积高饱和色块影响阅读。
5. 冲突信息需要突出“资源是什么、为什么冲突、现在能怎么处理”。
6. 规则包归类需要靠近可拷贝资源列表，避免用户在血缘树中寻找归类入口。
7. 所有主要操作按钮固定在弹窗底部，包括上一步、下一步、继续拷贝、终止拷贝、关闭。
8. 长内容区域内部滚动，底部操作区保持可见。

## 12. 校验与异常处理

1. 未选择来源项目、决策流、版本时，不允许查询资源或进入下一步。
2. 未选择任何资源时，不允许进入拷贝校验。
3. 接口加载中需要展示 loading，避免重复点击。
4. 来源资源为空时展示空状态。
5. 校验接口失败时停留在选择页，并提示失败原因。
6. 保存接口失败时停留在校验页，并保留用户已填写的重命名和规则包归类。
7. 后端返回未知 `module` 或 `typeTag` 时，前端展示原始枚举值，不中断流程。

## 13. 验收标准

1. 用户可以完整完成“选择来源资源 -> 校验 -> 处理冲突 -> 提交拷贝 -> 查看结果”的流程。
2. 前端真实后端模式下，请求路径与真实接口文档保持一致，均使用 `/copy/*`。
3. 前端 mock 模式和真实后端模式共用同一套页面组件和交互逻辑。
4. 前端不在组件中自行推导依赖树、冲突类型或可拷贝数量。
5. 用户填写的重命名编码最终进入 `conflictItems.itemNewCode`。
6. 用户选择或输入的目标规则包最终进入 `copyableItems.pkgId`、`copyableItems.pkgName`。
7. 大依赖场景下，血缘区仍能通过搜索、筛选、展开收起保持可读。
8. 保存完成页展示后端返回的 `copyCount`、`reuseCount`、`directCount`、`conflictCount`、`skipTotal`。

## 14. 待确认问题

1. 目标上下文是否后续由宿主系统注入，还是需要新增后端接口查询。
2. `/copy/projects/{projectName}` 和 `/copy/process/{projectName}/{process}` 是否支持空关键词。
3. `/copy/resources` 返回的 `resourceDetails` 当前缺少资源模块类型，若需同时展示规则和组件分类，建议后端补充 `module`、`moduleDesc`。
4. 冲突项是否需要返回“影响到的初始选择资源”或“影响到的目标资源”，以便页面展示冲突影响范围。
5. 新建规则包时，保存接口是否只需要 `pkgName`，以及同名规则包的处理策略。
6. 保存接口是否可能演进为异步任务。如果是，需要补充任务创建、进度查询和失败详情接口。

## 15. 当前实现说明

当前前端实现已按真实接口路径封装 API 适配层，并保留 mock 数据。

接入真实后端时，配置：

```env
VITE_USE_MOCK_API=false
VITE_RESOURCE_COPY_API_BASE_URL=http://backend-host
```

目标场景上下文可通过环境变量配置：

```env
VITE_TARGET_PROJECT_NAME=零售信贷项目
VITE_TARGET_PROCESS_KEY=credit_main
VITE_TARGET_PROCESS_NAME=信贷决策流
VITE_TARGET_PROCESS_VERSION=v3
VITE_TARGET_SCENE_NAME=生产场景
```

mock 模式仅用于前端演示和联调，不代表前端承担真实业务判断职责。
